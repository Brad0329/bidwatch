## 결정과 이유

- **정규화 방식 — 짧은 이름 통일 ("서울특별시" → "서울"):** 수집기마다 region 형식이 다름 (나라장터: "서울", 기업마당: "경기도"). DB 저장 시점에 normalize_region() 적용하여 짧은 이름으로 통일. ILIKE `%서울%`로 검색하면 정규화 안 된 데이터도 매칭되므로 하위호환 유지.
- **지역 목록 API — DB DISTINCT 대신 상수 반환:** DB에 수집된 데이터가 없는 지역도 드롭다운에 표시해야 함. 17개 시/도를 상수로 관리하여 일관성 보장.
- **멀티셀렉트 드롭다운 — 콤마 구분 문자열 전달:** API 파라미터: `region=서울,부산` (콤마 구분) → 백엔드에서 split → OR 조건 ILIKE. 단일 쿼리 파라미터로 처리하여 API 단순성 유지.
- **관심 지역 기본 필터 자동 적용:** useEffect + regionInitialized 플래그로 최초 1회만 적용. 사용자가 이후 수동으로 변경/해제 가능. 관심 지역 미설정 시 전체 지역 표시 (필터 없음).
- **tenant_profiles.region — 콤마 구분 문자열 저장:** ARRAY(String)으로 변경하면 마이그레이션 필요 → 콤마 구분 문자열로 저장하여 마이그레이션 회피. "서울,부산,경기" 형태.
- **프로필 API 신규 생성 (profile.py):** 기존에 프로필 라우터가 없었음. GET/PUT /api/profile/regions만 우선 구현 — Phase 3 AI 매칭에서 프로필 API 확장 예정.
- **검토요청 페이지에도 지역 필터 추가:** notices, pre-notices, review 3개 페이지 모두에 일관되게 적용.
