# 팩: LLM 생성 기능 (외부 LLM API로 콘텐츠를 생성하는 기능이 있을 때)

> 선택형 팩 — 이 프로젝트에 해당 없으면 이 파일을 삭제한다.
> 출처: hanjadic 프로젝트 실측(2026-08, DeepSeek API). 수치는 그 실측값이다.

## 비용·지연

- **추론(reasoning) 모델은 보이지 않는 추론 토큰이 지연과 요금을 지배한다.** 짧은 정형 출력
  작업이면 thinking을 끈다. 실측 18건: 추론 42~4,652토큰·경과 5.1~44.0초, 같은 입력 3회도
  널뛰었다. 끈 뒤 12건 전부 3.9~6.8초·형식 12/12·품질 동일. **화면에 안 보이는 토큰이
  요금의 60~80%였다.**
- **`max_tokens`로 추론을 제한하면 최악이다** — 추론이 예산을 먹어 본문이 잘리고 오히려
  더 느려진다(실측 143초 + 본문 절단). 프롬프트로 "생각하지 마라"도 보장이 없다.
- **`stream:false`면 타임아웃 = 모델이 생각을 끝낼 때까지의 제한이다.** 지연 분포의 꼬리를
  재고 타임아웃을 정한다(보통 3~6초, 꼬리 17~44초 — 표본 2건으로 정한 30초가 틀렸었다).
- **모델 선택은 벤치마크가 아니라 이 작업의 형식 준수율 실측으로.** 상위 모델이 형식을 더
  못 지킬 수 있다(실측: 하위 모델 4/4, 상위 모델 0/4 — 구분자를 전각으로 씀. 품질은 동일,
  하위 모델이 3~5배 빨랐다). 짧은 정형 작업은 추론 능력이 결과를 가르지 않는다.
- **생성 결과 캐시는 필수다(종량제).** 캐시 키에는 **(대상, 종류)** 를 넣는다 — 대상 문자열이
  다른 종류와 겹치면 서로 덮어쓴다(실제 사고). 선택·문맥이 결과를 가르면 그것도 키에 넣는다.
- **종량제 API는 명시적 조작(버튼)으로만 호출하고, 생성 중에는 중복 호출 경로를 잠근다** —
  중복 클릭이 곧 요금이다. 화면 진입·입력만으로 호출되는 경로를 만들지 않는다.
  "누르는 감각은 같은데 비용이 달라지는" UI 변경(무료 조회→유료 생성)은 사용자와 합의하고 기록한다.
- **요금이 나간 결과는 화면 생존과 무관하게 먼저 저장한다.** `if (!mounted) return`류 가드가
  캐시 쓰기보다 앞이면 응답 지연(3~17초) 중 화면 이탈로 결과가 버려진다 — 순서만 바꾸면 된다.
- **오류 표시에서 키 문제(401/403)와 잔액 부족(402)을 구분한다** — 사용자가 취할 행동이 다르다.

## 길이·모델 지시 (hanjadic 2026-08-20 실측)

- **★★ 길이는 "N자 내외"가 아니라 하한("최소 N자 이상")으로 지시한다.** 사용자가 `45자 내외`라
  썼는데 계속 30자쯤만 나왔고, 앱을 다 뒤졌지만 원인이 아니었다(`max_tokens` 안 보냄, 프롬프트
  저장 시 캐시 자동 비움, 후처리는 공백만). 조건 한 줄만 바꿔 재보니 갈렸다:

  | 조건 표현 | 모델 | 한자 수 |
  |---|---|---|
  | `45자 내외` | flash | 25, 14 |
  | `45자 내외` | pro | 14, 13 |
  | **`최소 40자 이상`** | flash | **49, 48** |
  | 구조로 지시(복문·부사구) | flash | 17, 21 |

  - **"내외"는 모델이 원래 쓰려던 길이 근처에서만 맞는다** — 기본값 `15자 내외`가 잘 나온 것은
    지시가 먹혀서가 아니라 그 길이와 겹쳐서다. 숫자를 바꾸면 조용히 무시당하고 원인을 앱에서
    찾게 된다. 상한처럼 읽히는 표현은 무시된다.
  - **모델을 올려도 안 된다**(pro가 오히려 더 짧았다). **구조 지시도 길이를 늘리지 못한다.**
    길이를 원하면 길이로 말한다.
  - 표본은 조건당 2건이다('표본 2건' 경고 적용). 다만 3배 차이라 방향은 분명하다.
  - 원인 추적 순서의 교훈: **앱(파라미터·캐시·후처리)을 먼저 배제**하고, 프롬프트가 그대로
    나가는지 미리보기로 확인한 뒤, **조건 한 줄만 바꿔 실측**한다.
- **모델 ID를 기억으로 쓰지 말 것** — 모델 목록 API(`/models`)로 확인한다. 기억 속 모델명
  두 개가 존재하지 않았던 실사례.
- **모델 선택 기능을 넣으면 캐시 키에 모델을 넣는다.** 두 모델을 오가면 항목 수가 최대 2배이고
  그것이 정상이다. 사전·DB에서 온 결과는 모델을 안 타므로 종류에 `usesAi` 같은 필수 구분을
  두어 새 종류를 더할 때 컴파일러가 잡게 한다.

## 형식·파싱

- **구분자·형식 예시로 모델을 길들이는 방식은 규모가 커지면 감당이 안 된다** — JSON 스키마
  요구로 전환한다. 단 전환 후에도 코드블록 벗기기·재인코딩 방어는 유지한다("늘 깨끗하게
  온다는 보장이 없다").
- **JSON을 요구하는 프롬프트에는 "문자열 값 안에 줄바꿈을 넣지 마라" 한 줄을 반드시 넣는다.**
  실측 8건 중 1건에서 모델이 값 안에 줄바꿈을 넣어 JSON이 깨졌다 — 파서가 형식 이탈로
  처리해도 **요금은 이미 나간 뒤다.** 새 JSON 프롬프트를 만들 때마다 이 줄을 빠뜨리지 말 것.
- **코드가 아는 값(대상·식별자·타입 태그)은 모델에게 시키지 말고 코드가 응답에 박는다.**
  프롬프트에 형식을 넣어도 모델은 실제로 빠뜨린다. 코드가 붙이면 틀릴 여지가 없고,
  재인코딩 과정에서 형식 규칙도 구조적으로 지켜진다.
- **형식 이탈은 이탈로 남기고 원문을 버리지 않는다.** 이탈 응답에 코드가 정형 접두를 붙이면
  "그럴듯한 정상 결과"로 둔갑한다. 파싱 실패 시 원문 보존 + 요금이 이미 나갔음을 전제로 설계.
- **LLM으로 만들 수 있어도 결정적 소스(사전·DB)에서 가져올 수 있으면 그쪽이 이긴다** —
  지어내기 0·요금 0·후속 동작 보장. LLM에게 물었다면 없는 항목을 지어내 "눌렀을 때 못 찾음"이
  났을 것이다. 결정적 소스와 LLM 추측을 한 목록에 섞지 않는다(근거를 구분할 수 없게 된다).

## 프롬프트를 사용자에게 열 때

- **지시문 / 대상 / 출력 스키마를 갈라, 지시문만 연다.** 스키마가 깨지면 모든 결과가 형식
  이탈이 되어 기능이 통째로 죽는다. 스키마는 프롬프트 맨 뒤에 붙인다(사용자가 지시문에
  형식을 또 써도 마지막 지시가 이긴다).
  - 예외: "밖으로 나가는 연결(버튼·탭)이 없는 출력"은 스키마까지 열어도 잃을 기능이 없다 —
    그 기준으로 부분 개방할 수 있다.
- **출력 key를 사용자가 정하는 자유 양식에서는 key 이름으로 아무것도 판정하지 않는다.**
  종류는 코드가 박는 예약 태그(`_` 접두)로, 언어·내용 판정은 값의 생김새로 한다.
- **프롬프트가 바뀌면 캐시를 비워야 한다 — 경로가 두 개다.** 코드 상수 변경은
  `promptVersion`으로, 사용자 편집은 저장 시 **그 종류만** 자동 비우기로. 안 비우면 프롬프트를
  고쳐도 옛 결과가 계속 나오고, 전부 비우면 돈이 두 번 나간다.
- **"내가 고친 프롬프트가 정말 나갔나"를 확인할 전문 미리보기 화면을 넣는다.** 코드가
  대상·스키마를 붙이므로 화면 없이는 사용자가 검증할 길이 없다. **프롬프트 종류를 추가할
  때 미리보기 등록 + 대조 테스트를 같은 커밋에 넣는다** — 등록 목록에서 한 종류가 빠져
  조용히 안 보이던 실사례(안내 주석으로는 못 막았다).
- **숫자 파라미터(길이·개수)를 슬라이더와 자유 프롬프트 양쪽에서 정하게 하면 어긋난다** —
  통제권을 한쪽에 몰아준다. 범위 제한이 필요한 값은 저장할 때와 사용할 때 양쪽에서 방어한다.
- **의존 기능들의 개방 순서가 재작업을 가른다.** 받는 형식(JSON 전환)을 먼저, 그 위의 자유
  프롬프트를 나중에 — 역순이면 사용자가 쓴 프롬프트가 옛 형식에 묶여 다시 손봐야 한다.
- **자유 양식 개방은 좁게 시작한다.** 한 종류만 열고 써 본 뒤 넓힌다 — 좁게 시작해 만든
  인프라(타입 태그·자유 렌더러)가 다음 기능에서 거의 공짜로 재사용됐다. 넓히는 쪽이
  좁히는 쪽보다 싸다.
