## 시스템 목표
- 입찰 담당자가 여러 공공 사이트를 매일 돌며 공고를 찾는 수고를 없앤다. 공공 API와 사용자가 지정한 사이트에서
  공고를 자동 수집하고, 회사(테넌트)별 키워드·지역·출처 기준으로 걸러 한 화면에서 보여준다.
  검토 워크플로(태그)로 팀 내 판단을 공유한다. 향후 회사 프로필 기반 AI 매칭(프리미엄)으로 확장한다.

## 사용자/권한
- **owner**: 회원가입 시 테넌트와 함께 자동 생성. 모든 권한.
- **admin**: 관리자설정(수집 실행·수집 통계) 접근.
- **member**: 공고 조회, 키워드·출처 구독·태그·관심 지역 관리.
- 모든 데이터 조회·변경은 로그인 필요. 테넌트 간 데이터(구독·키워드·태그·프로필)는 서로 보이지 않는다.

## 화면 방향

1. **UI 형태**: 웹 (Next.js)
2. **기준 기기·해상도**: 데스크톱 우선(사이드바 + 본문 레이아웃). 모바일 반응형은 '이후 단계'(성장)로 미룸.
3. **룩앤필의 기준**: (c) 프레임워크 기본 — Tailwind 유틸리티 + Remix Icon, 흰 카드·회색 경계선.
   초기 레이아웃 참고본은 `prototype/`(dashboard.html, notices.html).
4. **다크모드 / 접근성 / 언어**: 다크모드 없음 · 한국어만.
5. **새 화면 확정 방식**: 모양을 AI가 골라야 할 때만 목업(HTML 한 장)을 보여주고 확정한다.

## 비기능 요구사항

1. **인증 방식**: 계정(이메일+비밀번호, bcrypt) + JWT(access 30분 / refresh 7일, HS256). 테넌트 단위 격리, 역할 3종(F-002).
2. **공개 범위**: 인터넷 공개 SaaS 예정(회원가입 공개). 구체적 노출 표면(관리자 API의 IP 제한 여부 등)은 Phase 011에서 확정 — 미정.
3. **성능·기타**: 목록 페이지 크기 최대 100. 공고 10만 건+ 대응(FTS 전환 등)은 '이후 단계'. data.go.kr 일일 1,000회 한도 안에서 수집.
